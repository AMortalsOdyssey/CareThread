## 2026-07-31 / M2 OCR 与提取引擎

### 实现

- 定型 `OCREngine`：统一输出按页面排序的 `TextBlock(text, box, confidence)`；Vision 使用 `.accurate`、`zh-Hans + en-US`、语言纠错，全程设备本地。
- `ExtractionEngine` 保持纯函数：输入 OCR 文本和固定“今天”，输出机器层快照；没有 UI、数据库或外部状态依赖。
- 六份虚构病程样张及期望 JSON 原样落入测试目录，覆盖病理、出院、检验、超声、门诊与 CT。
- 规则细分为日期上下文优先、医院最长匹配、科室标签优先、类型加权/并列回退、指标显式与推导异常分层、医嘱段高置信、相对复查日期折算。

### 红绿循环

- 首轮 85 个单测中 10 个断言暴露三类真实问题：检验缩写数字被误认成结果、单位 `/L` 被误认成低标记、超声强证据不足。
- 修复解析规则后保留全部断言重跑；没有删除、跳过或弱化测试。
- 最终 `Scripts/verify.sh`：Swift Testing 85/85、XCUITest 1/1，退出码 0。

### 查漏

- [x] 六类样张类型、日期、医院、科室与关键字段
- [x] 指标 ↑/↓/H/L、区间推导与电话号码排除
- [x] 历史用药低置信、医嘱/处理段高置信
- [x] 1 月/3 月/2 周复查折算与“定期复查”不虚构日期
- [x] 空文本、未来日期、无效日期、10k 字性能
- [x] 至少 2 个真实 Vision OCR 闭环与空白图

## 2026-07-31 / 范围增补与审查启动

### 新增范围

- 用户要求当前交付增加最多 20 位成员的本地独立管理与快速切换。
- OCR 入库新增姓名一致性闸门：不一致时必须切换；仅“姓名识别错误”二次确认允许留在当前成员，并记录识别姓名、当前成员、原因与确认时间。
- `＋` 的更多功能新增复查提醒、用药提醒、本地通知与可选日历事件。
- 每位成员的原件 Vault 作为真实数据源，机器提取和人工确认均可重建；原件支持高清查看、系统导出/复制和 Files 目录访问。
- PDF 可按近 1 月、半年、1/2/5/10 年、全部导出单个成员资料，并使用系统分享面板交给微信等目标。
- 增加同一成员的本地跨期指标/事实对比；界面明确说明是离线规则整理、不是诊断或云端高级分析。
- 图片、拍照和文档继续支持；视频明确拒绝。

### 设计约束

- 当前成员只是查询/录入上下文，所有持久化对象必须显式携带不可空 `patientId`，不能依赖全局筛选器假定隔离。
- 原件目录以不可猜 UUID 作为磁盘键，不用姓名建路径；导出临时文件不得成为第二真实数据源。
- OCR 错配覆盖是受控例外，不是“强制添加”：需要用户主动选择原因并二次确认，且记录不能静默抹除审计信息。
- 提醒模型与系统通知/日历标识分离，权限拒绝时资料仍可保存；重复调度必须幂等。
- 所有导出、比较、搜索、删除、备份均先以 `patientId` 限定范围，再应用时间条件。
- 列表查询增加日期、病种/类型、医院、医生、事件年龄组合条件及确定性排序；分页游标绑定成员、筛选摘要和排序摘要，任一变化即作废。

### 并行审查

- 已启动数据安全/架构、UX/老人版、边界与对抗测试三路只读审查；根任务统一吸收结论后再实现，避免并行编辑覆盖。
- 用户允许项目全程轮换使用最多 20 个 subagent；受运行环境并发上限影响，同一时刻保持根任务加 3 个专项，完成后轮换性能/崩溃等审查。
- 新范围追踪见 [`SCOPE_ADDENDUM.md`](SCOPE_ADDENDUM.md)。

## 2026-07-31 / OCR 独立选型

### 基准实现

- 固化 6 张 P、16 张 H、8 张 D 和 1 张观察发票，全部来自虚构文本；系统三种指定字体均按原协议使用。
- Vision 和 RapidOCR PP-OCRv5 mobile 各预热后逐页跑 3 次；Rapid 模型逐一校验 SHA-256，推理期封死 socket。
- OCR 输出统一进入仓库实际 `ExtractionEngine`，统计日期、医院、类型、关键指标四类字段，没有为了候选修改提取规则。
- 新增独立 `OCRBench` iOS scheme；Vision 在 iPhone 16 / iOS 18.6 模拟器完成 30 页 × 3 次，P95 695 ms，指标保存在 xcresult 常驻附件并导出为 JSON。

### 结果与固定规则

- Vision：打印 CER 5.98%、手写 CER 3.92%、字段 113/120、Mac P95 229 ms。
- RapidOCR：打印 CER 2.34%、手写 CER 2.37%、字段 105/120、Mac P95 640 ms、arm64 增量上界 48.9 MB。
- 加权分：RapidOCR 79.74，Vision 40.00；Rapid 是分数胜者。
- 换引擎门槛：手写只改善 1.56 个百分点，低于必需的 10 个百分点；打印改善 3.64 个百分点。两条未同时通过，按 §5 唯一决定维持 Vision。
- ML Kit 因官方条款允许联系 Google 服务器并发送性能/使用指标而触发零联网红线；Tesseract iOS 包装因归档/旧上游出局；chineseocr_lite 因 GPL-2.0 出局。
