# CareThread 多报告、多页与多截图导入设计

## 1. 核心决策

一次选择或拍摄形成一个“导入批次”，批次中可以有多份“文档”，每份文档包含有序的“页面”。

用户确认的页面分组是唯一权威；本地 OCR 只能建议边界，不能静默把多张图片合并或拆开。原因是：

- 一份报告可能被截成多张屏幕截图。
- 一次可能选择多份报告，每份页数不同。
- 只有首页可能包含姓名、医院、检查名称和日期。
- 后续页可能只有表格续页，无法单页判断归属。
- OCR 识别失败或截图缺少页眉时，自动判断没有足够证据。

## 2. 数据层级

```text
ImportBatch（一次操作，冻结成员）
├── DocumentDraft 0（待确认的一份报告）
│   ├── CapturePage 0
│   ├── CapturePage 1
│   └── CapturePage 2
└── DocumentDraft 1
    ├── CapturePage 0
    └── CapturePage 1
```

- `ImportBatch`：批次 UUID、冻结 `patientId`、来源、状态、OCR/generation、创建/更新时间。
- `DocumentDraft`：批次 UUID、文档序号、分组 revision、报告级候选字段、姓名聚合结果和保存状态。
- `CapturePage`：稳定 UUID、批次/文档/成员 UUID、原选择序号、组内页序、staging 原件、页级 OCR generation/状态/证据。
- 提交后每个页面对应一份 `Attachment`；同一文档只生成一条 `MedicalRecord`，附件按稳定页序展示。
- 页级 OCR 和报告级人工确认分层。重新识别不会覆盖用户确认的分组、页序或字段。

## 3. 不同入口的初始分组

| 入口 | 初始建议 | 是否必须检查 |
|---|---|---|
| VisionKit 连续扫描 | 同一次扫描先作为一份文档 | 是；可从任意页拆分 |
| 相机逐张拍摄 | 本次连续拍摄先作为一份文档 | 是 |
| 多选照片/截图 | 保留系统选择顺序，本地规则建议分界 | 是，进入整理页 |
| 单个多页 PDF | PDF 内页面先作为一份文档 | 是；原 PDF 保持原件 |
| 多选 PDF/文件 | 每个文件先作为一份文档 | 是；可合并相关文件 |
| 单张图片 | 一批次、一文档、一页 | 简化确认 |

任何入口都不能依据“本次一起选择”直接判定为同一报告。

## 4. 整理页工作台

顶部先显示：

- `已选 12 页 · 建议整理为 3 份报告`
- 当前成员；导入开始后冻结，切换成员不会改变本批次。
- “自动建议”说明：只根据本机 OCR，保存前由用户确认。

主体按文档分组纵向排列，页面使用缩略图 + 页码 + 识别状态。文档之间有明显的“新报告从这里开始”分隔条。

每页必须有无需拖拽也能完成的操作：

- `从这里开始新报告`
- `并入上一份`
- `移到上一页 / 下一页`
- `删除本页`
- `旋转`
- `查看原图`

支持多选后“合并为一份”“拆成新报告”，但拖拽只作为快捷方式，不是唯一方式。

页面底部固定动作：

- `返回继续添加`
- `确认：3 份报告，共 12 页`

分组或页序变化后提升 `groupingRevision`，取消旧 OCR 聚合结果并重新计算建议。

## 5. 老人版

老人版不显示密集拖拽画布，采用逐页向导：

1. 大图显示当前页和上一页。
2. 两个不小于 60 pt 的主按钮：
   - `和上一页是同一份`
   - `从这一页开始新报告`
3. 另有 `看大图`、`上一页`、`下一页`。
4. 最后用大卡片汇总“共 3 份报告：3 页、5 页、4 页”，逐份可进入修改。

VoiceOver 读出“第 4 页，共 12 页；当前是第 2 份报告的第 1 页”。Reduce Motion 下不用位移动画表达分组结果。

## 6. 本地自动分组建议

建议只用于减少操作，不直接保存。每对相邻页面计算“同一文档”与“新文档”信号：

强同组信号：

- 明确页码连续，例如 `1/3 → 2/3`、`第 1 页 → 第 2 页`。
- 前一截图底部和后一截图顶部存在高比例 OCR 行重叠。
- 相同检查单号/报告号/就诊号（只在内存中规范化比较，不写日志）。
- 相同医院、科室、事件日期和报告标题，后一页缺少新的首页标志。
- 同一个多页 PDF 或同一次 VisionKit 扫描会话。

强分组信号：

- 相邻页出现可靠且不同的姓名。
- 后一页再次出现完整首页结构、`第 1 页`、新的报告号或明显不同日期/医院/报告类型。
- 用户已放置分隔线。

弱信号：

- 截图创建时间接近、版式/色彩相似、共同表头。
- 只出现相同医院但没有报告号或页码。

规则输出 `sameDocument / newDocument / uncertain` 和可解释原因。`uncertain` 必须保留明显的待确认状态，不能为了“智能”强行归组。

截图文字重叠只用于识别连续关系。原图永不裁剪或拼接覆盖；如果生成去重预览，它只是可删除派生物。

## 7. 姓名与归属聚合

姓名证据只能在同一个用户确认的文档组内聚合，不能跨批次或跨文档继承。

| 页级证据 | 文档级结果 |
|---|---|
| 首页可靠命中当前成员，后续页无姓名 | `match`，后续页在本组内继承归属 |
| 所有页无可靠姓名 | `noEvidence`，提示核对后可继续 |
| 任一页可靠识别为另一成员 | `mismatch`，整份拦截并建议拆分/切换 |
| 同组出现两个不同可靠姓名，或同名候选对应多个成员 | `ambiguous`，整份拦截并要求拆分/选择 |
| OCR 迟到但 grouping revision 已变化 | 丢弃旧结果，不改变当前分组 |

“姓名识别可能有误”的二次确认仍作用于整份文档，并在审计中保存每个产生冲突的页面 UUID 与证据摘要。覆盖不能把同一批次的其他文档一并保存。

## 8. 报告级字段汇总

- 首页字段优先，但不是无条件相信首页。
- 多页相同值提升置信度；冲突值并列展示，让用户选择。
- 日期、医院、医生、报告类型、报告号均保留来源页 UUID。
- 表格跨页指标逐页正规化后合并；相同指标是否为重复截图通过报告号、页码和 OCR 重叠判断，不以名称相同直接去重。
- 没有项目名称的续页在同组内继承报告标题；离开该组后不继承。
- 用户确认值写入报告层，页级机器值仍保留用于解释和重新整理。

## 9. 状态与失败恢复

批次状态：

`collecting → grouping → recognizing → review → committing → completed`

另有 `paused / failedRecoverable / cancelled`。非法跳转拒绝。

- 每页独立 OCR，专用 actor 并发 1；页面多不导致多张 48MP 位图同时解码。
- 每完成一页即持久化轻量状态，App 强杀后回到整理页。
- OCR 失败只标记该页，不丢弃其他页和用户分组。
- 提交以一份文档为事务单元；同一批次可先修正失败文档，已完成文档不重复写。
- 原件 staging 在批次取消时进入可清理 journal；不能留下无数据库引用的长期副本。

## 10. 规模边界

一期默认：

- 单批最多 100 页。
- 单份文档最多 50 页。
- 超限时不截断已选内容，明确提示分批导入。
- 缩略图和 OCR 使用下采样派生物；原件通过 URL/流式 I/O。
- 整理页只加载可见缩略图，不同时创建全部高清 `UIImage`。

这些数值在性能阶段通过 48MP 图片、长 PDF 和内存门槛复核；若调整，必须同时更新 UI 文案和自动化。

## 11. 自动化矩阵

- 单份 1 页、单份 N 页、N 份各 1 页、N 份混合页数。
- 只有第一页有姓名；只有中间页有姓名；全部无姓名。
- 同组出现不同姓名、同名多成员、OCR 姓名误识别覆盖审计。
- 多页 PDF、多选 PDF、截图混合、选择顺序与页序重排。
- 页码连续、页码缺失、重复页码、截图文字重叠、重复截图。
- 自动建议正确/错误/不确定，用户拆分/合并后旧建议不得回写。
- 快速切成员、OCR 迟到、App 强杀恢复、单页失败重试。
- 第 101 页和单文档第 51 页稳定拒绝且不丢已有草稿。
- 文档 A 提交失败不污染 B；批次内跨成员/跨文档引用拒绝。
- 标准版与老人版均可无拖拽完成拆分、合并、排序、查看和确认。
