# CareThread 新增范围与验收追踪

> 记录 2026-07-31 用户新增的当前交付范围。此文档只追踪实现和验收，不修改原交付包任务书。

## 1. 多成员与隔离

- 最多创建 20 位成员；第 21 位必须被稳定拒绝且不产生半成品目录或数据库对象。
- 首页、录入流程和管理页均可快速切换当前成员；切换必须刷新所有成员限定查询。
- 记录、附件、用药、医嘱、复查、提醒、导出和比较均显式绑定 `patientId`。
- 删除成员必须只删除该成员记录与 Vault；其他成员字节级不受影响。

## 2. OCR 姓名一致性闸门

- 姓名相同或 OCR 未识别出姓名：允许进入正常确认流程；未识别时显示“请核对姓名”。
- 姓名与当前成员不同：禁止直接保存，并优先提供切换到已有同名成员。
- 只有用户点击“姓名识别可能有误”并完成二次确认才可继续；保存识别姓名、目标成员、覆盖原因、确认时间和引擎标识。
- 不提供无说明的“仍然添加”或隐藏式强制添加。

## 3. 本地提醒与更多功能

- `＋` 的更多功能至少包含：复查提醒、用药提醒、手动记录、从文件导入、导出成员资料。
- 本地通知与系统日历写入分别请求权限；拒绝、受限、取消时不影响资料保存。
- 系统日历可能按用户的 iCloud/系统账户同步；写入必须单独触发并明确提示，不能将其宣称为纯本机能力。
- 同一业务提醒重复保存必须幂等；修改/删除同步撤销旧通知和已关联日历事件。

## 4. 原件真实数据源

- 原图片/文档采用不可变 Vault 保存；工作副本和缩略图均可从原件重建。
- 支持原图缩放高清查看、系统文件导出/复制，以及“在我的 iPhone”可见的导出副本目录。
- 受保护的真实 Vault 位于 Application Support，不直接暴露给 Files；可见目录中的文件明确标注为副本，外部修改不回写真实源。
- 文件路径不含姓名等隐私文本；防路径穿越、同名覆盖、跨成员读取和孤儿泄漏。
- 图片、拍照和文档可导入；视频按类型和扩展名双重拒绝。
- 一次导入可以包含多份报告，每份报告可以包含多页或多张连续截图；用户确认的分组与页序是权威，OCR 只提供可解释建议。
- 姓名、报告标题和项目只可在同一已确认文档组内继承；一组出现不同可靠姓名时必须拆分、切换或走明确的识别错误二次确认。

## 5. PDF 导出与分享

- 单成员范围：近 1 月、半年、1 年、2 年、5 年、10 年、全部。
- 边界使用固定时钟和闭区间定义；导出内容、原件引用、记录数与筛选范围一致。
- PDF 生成后进入系统分享面板，可由用户选择微信等已安装 App；App 不内置微信 SDK 或联网发送代码。
- 分享取消、目标不可用或临时文件清理失败均有可恢复状态。

## 6. 本地跨期对比

- 同一成员可选择当前阶段与历史阶段，比较同名同单位指标、用药变化、复查与文本事实。
- 缺失值、单位不同、参考区间变化、OCR 低置信度必须显式展示，不做虚构换算或诊断推断。
- 固定说明：结果来自本机规则整理，仅供资料回顾，不提供诊断建议。
- 高级云端/厂商健康能力只列为未来扩展，不在当前 App 引入联网代码。

## 7. 安全、字段与扩展性

- 模型字段有稳定语义和版本；关键枚举使用持久化原始值，新增值必须向后兼容。
- 数据库引用原件 Vault 的稳定相对路径与校验摘要；原件缺失/损坏可诊断而不崩溃。
- 敏感文件采用 iOS Data Protection，日志不含病历正文、姓名或导出内容。
- 备份、恢复、导出和删除均进行成员范围与完整性校验。

## 8. 自动化最低覆盖

- 20 人上限、跨成员零泄漏、切换中录入归属、姓名错配三分支与覆盖审计。
- 通知/日历权限拒绝、重复调度、修改和删除。
- Vault 高清原件、路径穿越、损坏、跨成员读取、视频拒绝。
- 七个导出时间范围、日期边界、分享取消、PDF 内容范围。
- 指标缺失、单位不一致、参考区间变化、低置信度与跨期比较。
- 标准版和老人版的关键路径均有 UI 测试与无障碍标识。

## 9. 组合筛选、排序与分页

- 所有记录视图先锁定当前成员，再支持日期范围、病种/记录类型、医院、医生、事件年龄等组合筛选。
- 支持至少按事件日期、录入日期、医院和记录类型排序，并提供升序/降序。
- 手机首屏使用横向可滚动的已选条件摘要和独立筛选面板，不把全部控件堆在列表顶部。
- 采用稳定游标或确定性分页；加载更多不能重复、跳项或跨成员，筛选/排序变化后重置游标。
- 空结果、加载中、加载失败、筛选无结果、到达末页均有独立状态；VoiceOver 可读出筛选数量和排序方向。
- 自动化覆盖日期闭区间、多个条件交集、同名医院/医生、年龄边界、切换成员时分页失效、删除中翻页和 300+ 记录流畅度。

## 10. 原生 iOS 与二期 Android

- 一期使用 Swift、SwiftUI、SwiftData 和 Apple 原生系统框架，不引入跨端运行时。
- Android 属于二期，不要求一期 UI、数据库或 Apple 系统能力迁就 Android。
- 一期需保持领域数据可迁移：稳定 UUID、枚举原始值、时间/时区、单位、版本化 JSON 与备份清单含义清楚。
- OCR、提醒、文件存储、导出和设备传输通过协议隔离平台实现；Apple 专属标识保留在适配层。

## 11. iOS 附近同步与换机

- 支持用户主动把单个成员或全部成员资料同步/迁移到另一台 iPhone。
- 主线采用 Apple 当前推荐的 `Network.framework + Bonjour + includePeerToPeer`，不在新功能中采用已弃用的 MultipeerConnectivity。
- 两端显示同一短配对码并分别确认；业务清单和文件逐块加密，接收端校验版本、数量、字节与 SHA-256。
- 接收端先写受保护 staging，全部通过后事务导入；断线、取消、磁盘不足、版本不兼容和篡改不能污染现有数据。
- 支持重复执行：相同 UUID 与内容幂等跳过，不同内容绝不静默覆盖，也不传播远端删除。
- 原“零联网代码”红线精确修订为“零互联网、零服务端、零后台常驻”；本地网络只在用户进入附近同步页面后启用。
- AirDrop/文件导入只作为加密备份包的手动兜底。
- 自动化覆盖协议和导入事务，尽力完成双模拟器；无线发现、点对点链路、网络切换和长文件恢复列入双真机验收。

详细技术、安全与测试设计见 [`NEARBY_SYNC_DESIGN.md`](NEARBY_SYNC_DESIGN.md)，全部追踪编号见 [`REQUIREMENTS_TRACEABILITY.md`](REQUIREMENTS_TRACEABILITY.md)。

## 12. 多报告、多页与多截图

- 数据结构区分一次导入批次、批次内多份文档、文档内有序页面。
- 多选照片/文件后进入整理页；支持从任意页拆分、合并上一份、无拖拽排序、删除重复页、旋转和查看原图。
- 本地 OCR 结合页码、报告号、医院/日期/标题、姓名和上下截图文字重叠建议边界，`uncertain` 不强行归组。
- 首页面姓名命中、续页无姓名时可在同组继承；跨文档不继承；组内出现不同姓名或多人候选则整组拦截。
- 标准版提供缩略图工作台，老人版提供“和上一页同一份 / 从这里开始新报告”逐页大按钮。
- 默认单批最多 100 页、单文档最多 50 页；原件流式保存，OCR 串行，整理页只加载可见缩略图。

详细方案见 [`MULTIPAGE_IMPORT_DESIGN.md`](MULTIPAGE_IMPORT_DESIGN.md)。

## 13. 全业务内容可编辑

- 成员档案、记录标题/日期、医院、医生、多个病种、摘要、用药、指标、提醒、标签、问题清单、文档标题、分组和页序均提供手动编辑入口；标准版与老人版功能同等可达。
- 普通编辑不能修改稳定 UUID、`patientId`、不可变原件、内容哈希、原始 OCR 快照、归属审计或迁移版本等系统字段。
- OCR 值与人工确认值分层：重新 OCR 只能产生新机器快照，不能覆盖用户更正。
- 每次保存与实体更新在同一事务追加修订记录，支持查看修改时间/字段与撤销最近一次；修订正文不进入日志。
- 编辑、撤销、快速切换成员、并发保存、App 强杀恢复和跨成员越权均纳入自动化。

## 14. 社区需求采纳

- 增加单成员“就诊准备卡”：用户选择展示的过敏、当前用药、诊断、医生/医院、最近关键记录、待问问题和联系人，支持一页 PDF。
- 增加“问医生的问题/就诊笔记”，只由用户手动维护，不录音、不转写、不自动生成医学建议。
- 用药/复查记录可直接创建提醒；用药支持用户指定补药日期、稍后提醒、完成与停用，不推断治疗方案。
- 一条记录支持多个病种；指标原始名、规范名、人工确认名并存，别名合并需确认。
- 增加当前成员待整理收件箱、重复页提示、本地全文搜索、重要资料置顶和最近备份/迁移提示。
- 不采纳云端家庭协作、AI 医学解读、医院门户自动同步、诊室录音、保险计费和法律资料管理。
- iCloud/CloudKit/iCloud Documents 不得存储本 App 的个人健康资料；系统日历是否由用户账户同步是独立的系统行为，不等同 CareThread 数据同步。

需求证据、采纳理由和拒绝项见 [`USER_NEEDS_RESEARCH.md`](USER_NEEDS_RESEARCH.md)。

## 15. 主开发后的开源与发展路线调研

- 在 M0–M9 和一期验收完成后，独立研究开源许可、默认版权、套壳/抄袭保护、商标/软件著作权、低维护社区治理和安全披露。
- 同时比较完全免费、付费下载买断、免费核心+一次性解锁、版本升级收费、订阅和未来 AI 单独付费。
- 调研本地/离线病历及家庭健康档案同类产品，区分产品宣传、商店事实和独立用户反馈。
- 结论必须兼顾非盈利倾向、维护资源有限、社区信任、未来 Android 与保留商业化选择，给出唯一推荐路线和 12/24/36 月触发条件。
- 当前按用户决定使用标准 MIT License；报告必须诚实评估其允许商业复用/套壳的代价，并为品牌、商标、图标和高级模块另设边界。
- 增加“MIT 开源发布并推广 → 积累知名度 → 出售项目/业务资产”的退出路线，重点核验可售资产、贡献者版权链、App 转移与健康数据不可随意随交易转移。
- 最终产物固定为 `docs/OPEN_SOURCE_AND_SUSTAINABILITY_STRATEGY.md`，追踪项为 `Q01–Q11`。

## 16. PDF 分享品牌钩子

- 页首顶部绘制产品色横线、CareThread Logo 与产品名；末段绘制 Logo、产品名、一句话介绍和可扫描二维码。
- 一页就诊准备卡与多页病程导出复用同一个离线品牌渲染器，不通过网络拉取 Logo 或二维码。
- 官网 URL 由一个常量统一管理；官网尚未上线时使用公开项目页作临时落点，未来切换不改 PDF 布局代码。
- 自动化必须从最终 PDF 页面而非仅从原始二维码图片解码 URL，保证分享、栅格化和打印尺寸可用。

## 17. 上传资料重复拦截

- 同一次导入及当前成员历史资料先比较原件 SHA-256；精确命中为硬阻断。
- SHA 不同再比较离线视觉内容指纹，覆盖格式重编码、重新拍照、旋转、透视裁边和宽高比变化；不依赖运行时模型下载。
- 视觉未命中再比较 OCR 内容重叠，支持多页报告中的单页重传和整份聚合；报告号/日期明确冲突优先避免同模板误判。
- 视觉/OCR 只作为疑似重复软提示，用户必须显式确认；确认前重新扫描。精确重复、检测异常、原件损坏或语料持续变化均不能静默放行。
- 全流程严格限定当前成员；老人版无法安全处置时保留草稿和原件，转标准版复核。
